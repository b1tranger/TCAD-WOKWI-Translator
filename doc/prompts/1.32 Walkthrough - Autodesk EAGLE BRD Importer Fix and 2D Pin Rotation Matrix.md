## 1. Problem & Root Cause Analysis

When opening Autodesk EAGLE `.brd` files exported from Tinkercad or academic coursework, the canvas remained completely blank:

1. **Selector / XML DOM Mismatch & Missing Fallback**:
   - In `Translator.fromEagleBrd`, elements were queried via `doc.querySelectorAll('elements > element')`. In browser XML DOM implementations (Chrome, Edge), CSS child combinators on XML trees often return empty node lists due to namespace handling and casing conventions.
   - When empty, `fromEagleBrd` returned an empty components array `[]` instead of falling back to `fromEagleBrdRegex`, resulting in a blank canvas.
2. **Component Classification Gaps**:
   - The user's DLD Lab files contained authentic Autodesk EAGLE packages (`74HC08_PDIP`, `74HC32_PDIP`, `74HC00_PDIP`, `74HC04_PDIP`, `74HC11_PDIP`, `74HC86_PDIP`, `SPST-478B04ST`, `SPST-678B06ST`, `LEDRD254W60D565H860B`, `BATTERY-GENERIC`, `LIGHTBULB`).
   - Many of these were unclassified and defaulted to `generic-component`.
3. **Pin Coordinates & Rotation Offset in Renderer**:
   - In `renderer.js`, components were transformed with `translate(x, y) rotate(deg)` around their local origin $(0, 0)$. However, `getPinCoordinates(comp, pinName)` computed pin locations assuming zero rotation, causing wires to disconnect or miss pins on chips and switches rotated by $90^\circ$ or $180^\circ$.
4. **Standalone `circuit.html` XML Parser Limitation**:
   - Standalone `circuit.html` exports only supported JSON in `loadCircuitJson(text)`, crashing with `SyntaxError: Unexpected token '<'` when users dropped or opened `.brd` files directly.

## 2. Changes Made

### A. Resilient DOM & Regex EAGLE Ingestion (`js/translator.js`)
- Replaced `doc.querySelectorAll` with `doc.getElementsByTagName('element')` and `doc.getElementsByTagName('signal')`.
- Added automatic fallback to `fromEagleBrdRegex(xmlStr)` whenever `elements.length === 0`.
- Built unified `classifyEagleComponent(name, value, pkg, library)`:
  - 74HC series logic gates: `74HC00`, `74HC02`, `74HC04`, `74HC08`, `74HC11`, `74HC32`, `74HC86`, `74HC132`.
  - DIP switches: `SPST-478B04ST`, `SPST-678B06ST`, `78B*`.
  - LEDs: `LEDRD254W60D565H860B`, `LIGHTBULB`, `RED`/`GREEN`/`BLUE`.
  - Power & Battery: `BATTERY-GENERIC`, `P1` $\rightarrow$ `battery-aa-4` / `power-supply`.

### B. 2D Pin Rotation Transformation Matrix (`js/renderer.js`)
- Replaced hardcoded unrotated pin coordinate calculations in `getPinCoordinates` with an exact 2D rotation matrix:
  $$\begin{pmatrix} rx \\ ry \end{pmatrix} = \begin{pmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{pmatrix} \begin{pmatrix} lx \\ ly \end{pmatrix}$$
  $$x = \text{comp}.x + rx, \quad y = \text{comp}.y + ry$$
- Extended DIP-14 pin mapping to all `comp.type.startsWith('chip-')` and `dip-ic` models.
- Mapped DIP switch pins 1..4 (bottom row, $y=84$) and 8..5 (top row, $y=6$).
- Mapped LED pins `1` (anode) and `2` (cathode) to their respective lead pads.
- Enhanced `getDipIcSVG` to automatically detect gate types (AND, OR, NOT, NAND, NOR, XOR, 3-AND, Schmitt, Timer) and display them in the silkscreen and floating badge.

### C. Standalone `circuit.html` Embedded XML Parser (`js/translator.js`)
- Injected `parseEagleXml(xmlStr, fileName)` into `exportStandaloneHTML`.
- Updated `loadCircuitJson` to detect XML tags (`<?xml`, `<eagle`, `<board>`, `<signals>`) or file extensions (`.brd`, `.xml`), parse them dynamically, and render them with full interactivity.
- Added dynamic SVG rendering for DIP ICs, DIP switches, and batteries in standalone `renderDynamicSvg`.

### D. Asset Versioning & Documentation Sync
- Updated asset query strings in `index.html` to `style.css?v=0.1.16` and `app.js?v=0.1.16`.
- Synchronized release notes in `doc/versions.md`, `doc/DOCUMENTATION.md`, and `README.md`.
