# Walkthrough: Standalone HTML Export and Diagram JSON Loading Fix (v0.1.15)

## Problem & Root Cause

When opening [`circuit.html`](file:///C:/Users/gsmur/AppData/Local/Temp/MicrosoftEdgeDownloads/7a57e8c1-9d96-4667-8de0-dda5004f6ea1/circuit.html), the viewer displayed an empty canvas grid instead of the circuit defined in [`diagram.json`](file:///C:/Users/gsmur/Downloads/diagram.json).

### Root Causes
1. **Query Selector Mismatch**:
   In `js/app.js`, `btnExportHtml` queried `document.getElementById('circuit-svg')`. However, the visual breadboard canvas SVG element declared in `index.html` is `#circuit-canvas`. Because `circuit-svg` evaluated to `null`, `viewportGroup` was `null` and `renderedSvg` was exported as an empty string `""`, leaving `<g id="viewport-group"></g>` blank.
2. **Missing Dynamic Renderer & File Ingestion in Standalone Viewer**:
   The exported standalone HTML viewer lacked dynamic client-side rendering from its embedded data, and had no native way to open or drag-and-drop external `diagram.json` or `circuit.json` files.
3. **No Direct Local File Picker in Main App**:
   The main workspace required copy-pasting raw JSON or using public Tinkercad URLs rather than providing an "Open File" button or canvas file drag-and-drop.

---

## Key Changes Implemented

### 1. Canvas Viewport Selector & Auto-Render Safeguard (`js/app.js`)
- Updated `btnExportHtml` to query `this.renderer?.viewportGroup?.innerHTML || document.querySelector('#circuit-canvas #viewport-group')?.innerHTML || document.getElementById('viewport-group')?.innerHTML`.
- Added safety check: if `renderedSvg` is empty, it automatically triggers a render pass `this.renderer.render(this.project)` before capturing the DOM innerHTML.

### 2. Standalone HTML Viewer Overhaul (`Translator.exportStandaloneHTML` in `js/translator.js`)
- **Complete SVG Styling**: Embedded styles for `.canvas-component`, `.wire`, `.wire-terminal`, hover glow effects, drag-over outline, drop hint, and zoom controls.
- **Dual Data Embedding**: Injected both `#tcad-circuit-data` (Native schema) and `#wokwi-circuit-data` (canonical Wokwi `diagram.json`).
- **Dynamic Client-Side Renderer (`renderDynamicSvg`)**:
  - Automatically reconstructs component bodies (Arduino Uno, Half Breadboard, 16x2 LCD, Potentiometer, Pushbutton, LEDs, Resistors) and bezier wire curves if static SVG is missing or when a new file is loaded.
- **Interactive File Controls in Standalone Viewer**:
  - **Open File Button (`#btn-load-file`)**: Direct file picker for any `.json` file.
  - **Canvas Drag-and-Drop**: Dragging any `diagram.json` or `circuit.json` onto the standalone viewer immediately parses and renders it.
  - **Dual Export Buttons**: Download canonical Wokwi `diagram.json` or Native `circuit.json` directly from the standalone viewer.

### 3. Native File Ingestion in Main Workspace (`index.html`, `js/app.js`, `js/ui.js`)
- Added **"Open File" button (`#btn-open-file`)** in the header toolbar, mobile FAB menu (`#fab-open-file`), and Tinkercad import modal (`#btn-modal-choose-file`).
- Added **Canvas Drag-and-Drop** on `#canvas-container` with visual drag-over indicator (`.canvas-viewport.drag-over`). Dropping any `.json` file parses and loads it into the live workspace.
- Updated `importTinkercadProject` and `Translator.fromWokwi` to preserve diagram titles upon import.

### 4. Release Synchronization (v0.1.15)
- **`sw.js`**: Bumped `const CACHE_VERSION = 'v0.1.15';`.
- **`index.html`**: Updated badge to `v0.1.15`, style query to `style.css?v=0.1.15`, and script query to `app.js?v=0.1.15`.
- **`README.md`**: Updated version badge and roadmap checklist.
