# Implementation Plan - Wokwi Wire Connectivity, Breadboard Netlist Collapse & Pin Normalization

Fix the issue where wires are visible on the website canvas after loading a Tinkercad link, but fail to appear in Wokwi when exporting `diagram.json`.

---

## 1. Root Cause Analysis

Investigation of the official Wokwi documentation and exported `diagram.json` revealed two critical issues causing Wokwi to drop all wires:

1. **Wokwi does not have a breadboard simulator component**:
   - Wokwi has parts like `wokwi-led`, `wokwi-resistor`, `wokwi-arduino-uno`, but **no `wokwi-breadboard` element**.
   - In our current `toWokwi` export, the breadboard is exported as part `bb_main` with type `wokwi-breadboard-half`, and nearly all circuit wires connect to `bb_main` pins (e.g. `bb_main:bottom_rail_neg_1`, `bb_main:tn.15`).
   - When Wokwi loads the JSON, it fails to load `bb_main` and silently discards every wire connected to `bb_main`.
2. **Case sensitivity and pin naming discrepancies**:
   - `wokwi-led`: Wokwi strictly expects `A` (Anode) and `C` (Cathode). Our code was emitting lowercase `a` and `c`, causing Wokwi to drop direct signal wires as invalid pin connections.
   - `wokwi-pushbutton`: Wokwi expects `1.l`, `1.r`, `2.l`, `2.r`, while our code was emitting `1`, `2`.
   - `wokwi-potentiometer`: Wokwi expects `GND`, `SIG`, `VCC`.
   - `wokwi-photoresistor-sensor`: Wokwi expects `VCC`, `GND`, `DO`, `AO`.
   - `wokwi-hc-sr04`: Wokwi expects `VCC`, `TRIG`, `ECHO`, `GND`.
   - `wokwi-servo`: Wokwi expects `GND`, `V+`, `PWM`.

## 2. Proposed Changes

### Component: Translation Engine (`js/translator.js`)

#### [MODIFY] [`js/translator.js`](file:///d:/GitHub/OSS/TCAD-WOKWI-Translator/js/translator.js)

1. **`normalizeWokwiPin(wokwiType, rawPin)`**:
   - Implement a pin mapping function that translates internal and Tinkercad pin names to Wokwi's exact canonical pin identifiers:
     - `wokwi-led`: `a`, `anode`, `pos` $\to$ `A`; `c`, `cathode`, `neg` $\to$ `C`.
     - `wokwi-resistor`: `1`, `t1`, `terminal1` $\to$ `1`; `2`, `t2`, `terminal2` $\to$ `2`.
     - `wokwi-pushbutton`: `1`, `t1` $\to$ `1.l`; `2`, `t2` $\to$ `2.l`.
     - `wokwi-potentiometer`: `1` $\to$ `GND`; `2`, `wiper`, `sig` $\to$ `SIG`; `3`, `5v` $\to$ `VCC`.
     - `wokwi-hc-sr04`: `vcc` $\to$ `VCC`, `trig` $\to$ `TRIG`, `echo` $\to$ `ECHO`, `gnd` $\to$ `GND`.
     - `wokwi-servo`: `gnd` $\to$ `GND`, `v+`, `5v` $\to$ `V+", `pwm`, `sig` $\to$ `PWM`.
     - `wokwi-arduino-uno` / `mega` / `nano`: `gnd`, `gnd.1` $\to$ `GND.1`; `5v` $\to$ `5V`; `d0`..`d13` $\to$ `0`..`13`; `a0`..`a5` $\to$ `A0`..`A5`.
     - Pass-through for other known ICs and standard pins.

2. **Breadboard Netlist Collapse (`resolveBreadboardNets`)**:
   - Maintain breadboard rendering on the website canvas, but when exporting to Wokwi, collapse all breadboard ties into direct component-to-component connections:
     - Group connections and physically snapped component pins into electrical nets:
       - Power rails: `top_rail_pos`, `top_rail_neg`, `bottom_rail_pos`, `bottom_rail_neg`.
       - Tie columns: 5-hole terminal groups (`top_col_N`, `bottom_col_N`).
     - For each net with 2 or more component pins, connect the pins sequentially or star-connect from the power source (e.g. Arduino `GND.1` connects to resistor pin `2`, which connects to next resistor pin `2`, etc.).
     - LED cathode in column $k$ connects directly to resistor lead in column $k$.
   - Filter out breadboard parts (`breadboard-half`, `breadboard-full`, `breadboard-mini`) from Wokwi's `parts` array so Wokwi only receives real, simulatable components.

3. **Direct Wire Preservation & Case Normalization**:
   - For all wires connecting two non-breadboard components directly, normalize the pin names using `normalizeWokwiPin` and preserve wire colors (`red`, `black`, `green`, `yellow`, `blue`, `orange`, `purple`, etc.).
