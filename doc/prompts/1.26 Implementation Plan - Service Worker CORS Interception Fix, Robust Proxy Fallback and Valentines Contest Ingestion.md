# Service Worker CORS Interception Fix, Robust Proxy Fallback and Valentines Contest Ingestion (v0.1.14)

Fix the network, CORS, and Service Worker TypeError errors encountered when importing Tinkercad links (such as `https://www.tinkercad.com/things/lVMT4Ph4fKI-valentines-day-contest-entry`), make Tinkercad title resolution resilient, and enrich circuit synthesis for Valentine's contest and pedestrian crossing designs.

## Problem Analysis

### 1. Service Worker TypeError & Fetch Event Hijacking (`sw.js`)
When importing Tinkercad links, the browser console showed:
```text
The FetchEvent for "https://api.allorigins.win/raw?url=..." resulted in a network error response: the promise was rejected.
2sw.js:1 Uncaught (in promise) TypeError: Failed to convert value to 'Response'.
```
- **Cause**: `sw.js` intercepted all `GET` fetch requests unconditionally, including cross-origin requests to third-party domains (`api.allorigins.win`, `corsproxy.io`). When those external requests failed due to CORS or network errors, `sw.js` fell back to `caches.match(event.request)`. Since external URLs are not in the local cache and the request is not for an HTML page, `caches.match` resolved to `undefined`. Returning `undefined` inside `event.respondWith(...)` violates the Service Worker specification and throws `TypeError: Failed to convert value to 'Response'`, poisoning the fetch event and reporting an uncaught promise rejection.
- **Solution**:
  1. Add strict same-origin filtering: `if (!event.request.url.startsWith(self.location.origin)) return;`. The service worker will ignore external URLs and let the browser fetch them natively.
  2. In the `.catch()` handler, ensure `event.respondWith` never resolves to `undefined`: return a fallback `Response` object with an appropriate status code if no cached match exists.

### 2. Failing Third-Party CORS Proxies (`corsproxy.io` & `allorigins.win`)
- `corsproxy.io` has changed its policy and now returns `401 Unauthorized` without a paid API key.
- `api.allorigins.win/raw` frequently rejects cross-origin requests with CORS blocks.
- **Solution**:
  1. Rely first and foremost on the **instant, offline-capable URL slug parser** (`parseTinkercadUrl`). Public Tinkercad URLs already embed their full human-readable title in the URL slug (e.g. `lVMT4Ph4fKI-valentines-day-contest-entry` $\rightarrow$ `Valentines Day Contest Entry`).
  2. Remove `corsproxy.io` and replace with a non-blocking, safe fetch attempt to `api.allorigins.win/get` (which returns JSON `{ contents: "..." }` with proper CORS headers) wrapped in a silent `try...catch` and a short timeout. If it fails, seamlessly proceed with the slug metadata without throwing errors to the console.

### 3. Metadata Title Loss in `buildTinkercadTranslatedProject`
- In `buildTinkercadTranslatedProject`, line 2003 used `title: pageTitle || 'Tinkercad Circuit'`, ignoring `urlInfo.title`. When `pageTitle` was undefined, the circuit was labeled `'Tinkercad Circuit'` instead of its true title (`'Valentines Day Contest Entry'`).
- **Solution**: Use `const effectiveTitle = pageTitle || urlInfo.title || 'Tinkercad Circuit';`.

### 4. Valentine's Day Contest & Pedestrian Crossing Circuit Archetypes
- Detect `valentines|valentine|heart|love|contest` tokens:
  - Synthesize an authentic Valentine's contest circuit: Arduino Uno, Half Breadboard, 16x2 I2C LCD display (displaying `"Happy Valentine!"`), Potentiometer dimmer, NeoPixel RGB LED Strip / NeoPixel Ring, and Red/Pink LEDs arranged in a symmetric heart layout with complete power and signal wiring.
- Detect `pedestrian|crossing|crosswalk` in traffic light queries:
  - Add pedestrian walk/don't walk LEDs and crosswalk pushbutton connected to Arduino digital pins.

- Guard the cache fallback to always return a valid `Response` object.
- Bump `CACHE_VERSION` to `'v0.1.14'`.

  - Make proxy fetching completely non-blocking, using `https://api.allorigins.win/get?url=...` with JSON parsing.
