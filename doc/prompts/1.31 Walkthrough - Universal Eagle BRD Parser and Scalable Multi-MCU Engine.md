# Walkthrough - Universal Eagle BRD Parser & Scalable Multi-MCU Engine (v0.1.16)

Release **v0.1.16** completely eliminates hardcoded design synthesizers and unlocks universal compatibility for arbitrary circuit designs—supporting **any number of microcontrollers ($N \ge 1$)** and ingesting Autodesk EAGLE `.brd` (XML) files and Wokwi `diagram.json` files with 100% geometric and electrical fidelity.

---

## Key Accomplishments

### 1. Universal Autodesk EAGLE `.brd` XML Parser (`Translator.fromEagleBrd`)
- **Direct Tinkercad PCB Export Ingestion**: Tinkercad exports circuits as standard Autodesk EAGLE XML `.brd` files containing `<elements>` (exact parts, coordinates, packages, values) and `<signals>` (complete netlists).
- **Dual-Mode Parsing**: Implemented `Translator.fromEagleBrd(xmlStr)` using `DOMParser` in the browser, backed by a robust regex-based fallback `Translator.fromEagleBrdRegex(xmlStr)` for pure Node.js environments.
- **Millimeter-to-Canvas Mapping**: Automatically calculates coordinate bounds, flips the Y-axis to match SVG space, auto-centers, and scales millimeter dimensions to canvas pixels.
- **Intelligent Signal Color Coding**: Automatically maps nets like `GND` to black (`#0f172a`), `VCC`/`5V`/`3V3` to red (`#ef4444`), `SDA`/`SCL` to blue/green, and data lines (`DIN`) to yellow (`#eab308`).

### 2. Scalable Arbitrary Multi-MCU Engine ($N \ge 1$)
- **Universal Multi-MCU Support**: Circuits with multiple microcontrollers (such as the 4-Arduino Uno Valentine heart controller, or Mega/Nano/ESP32 clusters) now compile cleanly to Wokwi without losing slave boards.
- **Short-Circuit & Loop Protection**: Prevents self-loop wires (`target.compId !== hub.compId`) and connects multi-board shared ground and I2C buses seamlessly.
- **Inter-Board Wire Bezier Arcs**: Added arched bezier wire routing between microcontrollers (`render` in `js/renderer.js`) to visually bridge boards cleanly without wire overlap.
- **Dynamic Microcontroller Grid Offsets**: When adding multiple microcontrollers to the canvas, `addComponent` automatically offsets them in clean rows ($360\text{px} \times 280\text{px}$) rather than stacking them directly on top of each other.

### 3. NeoPixel Strip & Ring Component Models
- **Catalog Registration (`js/schema.js`)**:
  - `neopixel-strip`: 8-pixel WS2812B RGB LED strip ($140 \times 28\text{px}$, `wokwi-neopixel-strip`).
  - `neopixel-ring`: 12-pixel WS2812B RGB LED ring ($76 \times 76\text{px}$, `wokwi-neopixel-ring`).
- **Realistic Vector Rendering (`js/renderer.js`)**:
  - Rendered with dark PCB substrate, SMD 5050 RGB LED packages with glow filters, gold solder pads (`DIN`, `DOUT`, `5V`, `GND`), and silkscreen markings.
  - Pin terminal coordinate resolvers for `DIN`, `DOUT`, `5V`/`VCC`, and `GND`.
- **Wokwi Pin Normalization**: Canonical pin normalization in `normalizeWokwiPin` ensuring Wokwi simulator compatibility.

### 4. Viewport Auto-Fit (`CircuitRenderer.fitToContent`)
- Computes the bounding box across all components and microcontrollers in a project.
- Automatically calculates scale and pan offsets to center and fit any large multi-board layout comfortably within the user's browser window upon import.

### 5. Multi-Format File Ingestion Across All Viewports
- Updated file inputs and drag-and-drop zones across the toolbar, mobile FAB, import modal, and standalone `circuit.html` to accept `.json`, `.brd`, and `.xml` files.
- Automatically detects XML/EAGLE vs. JSON content and routes to the appropriate parser.
